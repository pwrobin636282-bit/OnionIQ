PRODUCT REQUIREMENTS
OnionGrade AI — Product Requirements Document
MVP / Hackathon PRD for SIH26031: AI-based onion quality assessment
SIH 2026 • Problem Statement SIH26031 • Medium
Product statement
OnionGrade AI is an AI-assisted digital onion assaying application that standardizes visible external quality assessment, converts computer-vision measurements into rule-based Grade A/URS outcomes, and produces an auditable digital quality report.
1. Problem Statement
SIH26031 identifies subjective and inconsistent onion quality assessment across procurement centres. The supplied research explains that the underlying process is multidimensional: size, shape/uniformity, skin condition, cracks/cuts, rooting, discoloration, neck condition, sun damage, sprouting, mechanical injury, smut, soft rot, bacterial/neck rot, fungal infection and moisture/dryness are relevant quality considerations.
The practical product problem is: large volume + multiple quality parameters + time pressure + human judgement can create inconsistent assessment risk. The solution should digitize the assessment layer while keeping the inspector in the decision loop.
2. Goals
Standardize image capture and visible external-quality assessment.
Detect onions and relevant visible defects from representative samples.
Estimate size/diameter and identify undersized bulbs.
Calculate lot-level Grade A, URS and Other/Rejected proportions using an explicit rules engine.
Explain every result with evidence, measurements, triggered rules and AI confidence.
Generate a digital quality assessment report instantly.
Support offline-first capture and later synchronization.
Reduce subjective variation without claiming to eliminate human bias or disputes.
3. Non-Goals / Explicit Limits
No claim of 100% AI accuracy.
No claim that smartphone images can reliably detect hidden internal rot, density, internal fungal infection or all moisture properties.
No fully autonomous final grading when the case is ambiguous.
No direct government-system integration in the MVP unless APIs/approval are actually available.
No custom foundation model training for the hackathon.
No farmer-facing account required for the MVP; the primary operator is the procurement inspector.

7. Rule / Grading Model
The architecture must separate computer vision from grading logic:
  Computer Vision  
→
  Measured Characteristics  
→
  Official/Configured Rules  
→
  Grade  
Example: AI detects sprouting = YES → applicable rule marks the relevant Grade A criterion as not satisfied.
The rule engine should store which rule version was applied to each lot.
The UI must explain the triggered rule in plain language.
Rules should be configurable so a future specification revision does not require retraining the CV model.
The supplied research references a 3.5–7 cm procurement diameter range and different tolerances for Grade A and Grade-URS; exact production rules should be encoded only from the approved specification used by the team.

9. AI Requirements
Use computer vision for onion/object and visible-defect analysis.
Use a deterministic rules engine for final grading.
Use an image-quality gate before CV inference.
Store model version and inference metadata with every assessment.
When confidence is below a configured threshold, route to Manual Review.
Do not represent AI confidence as probability of correctness unless the model has actually been calibrated for that interpretation.
10. Offline-First Requirements
Lot creation and image capture must work without network.
Assessment records should have a local state: DRAFT → CAPTURED → ANALYZED → REVIEWED → REPORT_READY → SYNC_PENDING → SYNCED.
Sync should be idempotent using stable local IDs.
Uploads should resume/retry without duplicating lots.
The UI must clearly distinguish local saved data from server-synced data.
11. Security & Privacy
Role-based access for operator/supervisor/admin functions.
Private storage for assessment images and reports.
Never expose backend secrets or model keys in the mobile client.
Validate image type and size; generate safe storage filenames.
Use encrypted transport for server communication.
Maintain an audit trail for creation, analysis, manual review, report generation and sync.
Apply least-privilege access to any future government or external integration.
